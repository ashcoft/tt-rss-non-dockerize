Tiny Tiny RSS — non-Docker install guide

This fork of tt-rss ships the Feedly theme and the Vue frontend, and is meant to be run straight from a checkout or a release tarball on a normal LAMP/LEMP host. Nothing here needs Docker; a container image is published as a convenience.

Requirements

ComponentVersion / notes
PHP8.2 or newer (8.3 is what the image uses). Needs pdo_pgsql, intl, mbstring, curl, gd, iconv, xml, zip, pcntl, posix, openssl, sodium, exif, fileinfo.
DatabasePostgreSQL (16 in docker-compose.yml); PostgreSQL is the only supported backend.
Web servernginx or Apache with PHP-FPM.
Composer 2Only needed if you clone the repository; release tarballs already contain vendor/.
Node.js 24 + pnpm 9Only needed to build the Vue frontend when running from a clone. Release tarballs already contain dist/.

Configuration is optional. tt-rss reads TTRSS_* environment variables directly, so a config.php is not required. Use whichever fits your host: environment variables in the FPM pool, or a config.php in the web root.

Native install (Debian/Ubuntu)

1. Packages

sudo apt install nginx postgresql php8.3-fpm php8.3-pgsql php8.3-intl \
    php8.3-mbstring php8.3-curl php8.3-gd php8.3-xml php8.3-zip \
    php8.3-opcache composer

2. Get the code

Either unpack a release tarball (it includes vendor/ and the built dist/):

sudo mkdir -p /var/www/tt-rss
curl -L -o tt-rss.tar.gz https://github.com/ashcoft/tt-rss-non-dockerize/releases/latest/download/tt-rss.tar.gz
sudo tar -xzf tt-rss.tar.gz -C /var/www/tt-rss

…or clone and build the frontend yourself:

git clone https://github.com/ashcoft/tt-rss-non-dockerize.git /var/www/tt-rss
cd /var/www/tt-rss
composer install --no-dev
corepack pnpm install --frozen-lockfile
corepack pnpm run build          # writes dist/, required by index.php

3. Database

sudo -u postgres createuser --pwprompt ttrss
sudo -u postgres createdb --owner=ttrss ttrss

4. Configure

Create /var/www/tt-rss/config.php (it is gitignored, and the image never ships one):

<?php
putenv('TTRSS_DB_HOST=127.0.0.1');
putenv('TTRSS_DB_PORT=5432');
putenv('TTRSS_DB_NAME=ttrss');
putenv('TTRSS_DB_USER=ttrss');
putenv('TTRSS_DB_PASS=change-me');
putenv('TTRSS_SELF_URL_PATH=https://reader.example.com/');
// putenv('TTRSS_SINGLE_USER_MODE=true');   // only behind your own auth

SELF_URL_PATH is optional: by default the URL is derived from the Host header. Set it (and optionally putenv('TTRSS_FORCE_SELF_URL_PATH_USAGE=true')) when a reverse proxy rewrites the host.

5. Create the schema

sudo -u www-data php /var/www/tt-rss/update.php --update-schema=force-yes

Then make the writable directories belong to the PHP user:

sudo chown -R www-data:www-data /var/www/tt-rss/cache \
    /var/www/tt-rss/feed-icons /var/www/tt-rss/lock

The first login is admin / password. Change it immediately, or set TTRSS_SINGLE_USER_MODE=true when the whole site sits behind your own authentication.

Web server

Minimal nginx site, assuming PHP-FPM listens on the default socket:

server {
    listen 443 ssl http2;
    server_name reader.example.com;

    root /var/www/tt-rss;
    index index.php;

    client_max_body_size 32m;

    location ~ ^/(config\.php|\.) { deny all; }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    }

    location / {
        try_files $uri $uri/ =404;
    }
}

To embed tt-rss in another origin's iframe (a Nextcloud “external site”, for example), send a frame-ancestors policy instead of X-Frame-Options: 

add_header Content-Security-Policy "frame-ancestors 'self' https://cloud.example.com" always;

/healthz is rewritten to public.php?op=healthcheck by the container's nginx config; on your own server add location = /healthz { rewrite ^ /public.php?op=healthcheck last; } if you want the same probe.

Fetching feeds

Either a cron job:

*/30 * * * * www-data /usr/bin/php /var/www/tt-rss/update.php --feeds --quiet

or the daemon, which is better for many feeds (systemd unit):

[Unit]
Description=tt-rss feed updater
After=network.target postgresql.service

[Service]
Type=simple
User=www-data
ExecStart=/usr/bin/php /var/www/tt-rss/update_daemon2.php
Restart=on-failure

[Install]
WantedBy=multi-user.target

Container image

Every push to main publishes a multi-arch image to GHCR. It bundles nginx, PHP-FPM and the built Vue bundle, listens on port 8080, and is configured entirely through TTRSS_* variables: 

docker run -d --name tt-rss -p 8080:8080 \
  -e TTRSS_DB_HOST=db -e TTRSS_DB_NAME=ttrss \
  -e TTRSS_DB_USER=ttrss -e TTRSS_DB_PASS=secret \
  -e TTRSS_SELF_URL_PATH=http://localhost:8080 \
  -e TTRSS_UPDATE_SCHEMA=1 \
  -v tt-rss-cache:/var/www/html/cache \
  -v tt-rss-icons:/var/www/html/feed-icons \
  ghcr.io/ashcoft/tt-rss-non-dockerize:latest

TTRSS_UPDATE_SCHEMA=1 runs update.php --update-schema before the server starts, which is what makes a first boot and every upgrade work unattended. The repository's docker-compose.yml wires the app to PostgreSQL and adds an updater service running update_daemon2.php.

Tags: latest (default branch), the branch name, sha-<commit>, and {{version}} / {{major}}.{{minor}} for v* tags.

Upgrading

  1. Back up the database (pg_dump) and feed-icons/.
  2. Replace the application files (tarball, git pull, or a new image tag).
  3. Run php update.php --update-schema — the container does this for you when TTRSS_UPDATE_SCHEMA=1.
  4. Reload PHP-FPM so opcache picks up the new code: systemctl reload php8.3-fpm.

Troubleshooting

SymptomLikely cause
Blank page or a “dist/ missing” errorThe Vue bundle was never built. Run pnpm run build, or use a release tarball that already contains dist/.
“Schema version is wrong”Run php update.php --update-schema=force-yes.
Feeds never updateNo cron entry and no update_daemon2.php process, or the PHP user cannot write to cache/ and lock/.
“Unable to connect to database”Check the TTRSS_DB_* values reach PHP. With a hand-written FPM pool, clear_env must be no.
Favicon/preview images brokenPHP lacks gd (or exif), or feed-icons/ is not writable.
Logins loop behind a proxySet TTRSS_SELF_URL_PATH to the public URL and enable TTRSS_FORCE_SELF_URL_PATH_USAGE.
